## 2. 本轮新证据与新发现

### 2.1 修复质量抽查（通过）

- `PlanSteps` 的 `EnterNested/ExitNested` 包在 try/finally 里，无计数泄漏；`Global` 步骤在主线程嵌套抑制是刻意的。
- `ProcessingPlan.Execute` band 并行后契约变更（kernel 必须线程安全）已写入文档注释，`List.Add`→`ConcurrentBag` 测试修复正确。
- AOT 冒烟语料**已扩展覆盖新内核**（median.sobel / equalize / bilateral 的 hash 在 `AotSmoke/Program.cs`）——我上轮预设的这个缺口不成立，撤回。
- Gaussian 窄图 OOB 修复（`FilterOps.cs:178` `Math.Min(radius, width)`）在位，且回退验证过测试会变红。

### 2.2 新发现（本轮三个）

1. **P1：`Convolve2D` / bokeh 的 worker 缓冲是 `new float[]`，不是 `FloatScratch.Rent`**（`FilterOps.cs:1049-1051`）。每次调用每 worker 分配 side×stride floats（81 taps ≈ 311 KB，bokeh r=6 ≈ 449 KB），16 worker 并发一次调用即 ~5–7 MB 垃圾。这与全库"稳态 0 分配"的纪律和 `FloatScratch` 的存在自相矛盾，known-gaps 未登记。
2. **P2：`Global` 步骤的嵌套抑制误伤内部并行**。`Global` 在主线程 EnterNested，导致 plan 内的 Equalize/CLAHE 应用阶段被压成单线程（它们自己的 `RowParallel.For` 读到 nesting=1）。正确性无损，纯性能损失。
3. **P1：三档 SIMD 字节一致性矩阵未随新内核复跑**。589 测试是在默认档跑的；AGENTS.md 承诺的 `EnableAVX512F=0 / AVX2=0 / HWIntrinsic=0` 三遍矩阵，在 409→589 的膨胀过程中没有留下复跑证据。median3x3 的 `Vector128<byte>` 比较交换、Convolve2D 的 `Vector256<float>` 累加都是新 intrinsic 使用面，跨档位一致性应补一次矩阵证据。

### 2.3 对方抓到、我上轮漏掉的真缺陷（记录在案）

"414 中 1 失败"的偶发测试不是测量噪声，是**真实越界写**：Gaussian 平面化横向前缀循环只以 radius 为界没以 width 为界，11px 宽图配 σ5（radius 15）时写越过 `8*width`；`FloatScratch` best-fit 返回更大缓冲时**静默写脏相邻平面**，恰好等大时才抛异常。纯色测试图让断言从未报错——**静默污染 + 纯色夹具**双重掩盖。已修 + 144 用例尺寸×σ 扫描 + 回退验证。
这暴露的是**夹具系统性盲区**（所有 golden 都是宽图），他们的应对（尺寸扫描 + 非纯色窄图用例）是对路的。

### 2.4 流水线战场的"3/3 胜"有一个被污染的格子

`point-3` 的 5.22× 建立在对手 45.1 ms 上——对手 5 个点算子 15.8 ms、3 个不可能 45.1 ms。这和他们自己推翻过的"point-3 2.66× 预热假象"是**同一类对手测量污染**。point-5 的 1.26× 和 blur-point 的 1.21× 站得住；**几何平均 1.9954× 不应引用**，应引用"3/3 翻正、幅度 1.2–1.3×（point-3 幅度存疑）"。

## 3. 对 11-07 对比协议的评价

做对的（这是三轮以来方法论最好的一版）：

- 跨尺寸矩阵 + 翻面标记，自己得出"单分辨率结论不成立"；
- 双协议互证（吞吐 perf vs 最小延迟 cores），并明确两者不可混用；
- 无对等实现的算子**不给倍数**、brightness 语义不同只展示不给倍数——对标纪律干净；
- `resize-nearest` 那格自查出"0.031 ms 不可复现、比值不报"——对噪声的诚实度显著提升；
- cores 协议推翻了自家早前"每核落后 4 倍"的结论，改为"同核 1.1–1.3× 偏慢"并承认分项 ±40% 只有汇总可引用。

仍要盯的：

- "分辨率越大越领先，单调上升"建立在一次 sizes 运行上；per-item ±40% 的波动下，单调性结论应标注"本轮观察"。
- audit-response 引用的 1.7304× 与 compare 报告的 1.8068× 是不同 run，两份文档各自裸引——统一成"范围 + 中位数"格式。
- AGENTS.md 写"585 tests"，实测 589——文档滞后（小，但这是以精确为卖点的仓库）。
