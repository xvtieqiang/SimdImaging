# Domain Transform 滤波：评估，以及为什么不落地

**结论：不落地。** 它不新增能力（保边平滑已有 `GuidedFilter` / `Bilateral` / `LocalLaplacian` 三条路），
而它的成本结构与本库的口径相冲：核心是行内串行递归 + 每像素 `exp`，横向遍无法向量化；论文相对
bilateral 的卖点「代价与 σ 无关」在本库已经由箱均值的 O(1)/px 拿到。本文把算法拆开、把算术量和已有
实测放在一起，供 M15 复评。

机器口径：本机（x64，AVX2，无 AVX-512），2026-11-14，`benchmarks/SimdImaging.Benchmarks`，4K Rgba8，
`best-of-3` 预热后读数。协议见 `benchmarks/README.md`。

## 1. 算法是什么

Gastal–Oliveira（SIGGRAPH 2011）把图像映射到一个「测地线距离等于像素距离」的域上，再在一维做递归滤波。
一次迭代、一个方向：

1. **变换**：沿扫描线积分 `ct(x) = ∫₀ˣ 1 + (σs/σr)·|I′(t)| dt`。相邻像素的 `|Δct|` 就是它们在该通道上的
   测地距离 —— 颜色变化大的地方距离被拉长，滤波因此不跨边缘。
2. **递归滤波**：`y[i] = (1 − a_i)·x[i] + a_i·y[i−1]`，`a_i = exp(−√2/σs · |Δct|)`。
3. **归一化**：用同一组 `a_i` 对常数 `1` 再滤一遍，逐像素相除。
4. 水平、垂直各做一次为一轮；彩色图按论文做 **3 轮**（每轮 σs 放大）。

论文给了 NC / IC / NR / IR 四种组合，效果最好的是 IR（interpolated recursive）。「domain transform」
指的是域的变换，不是距离变换 —— 见下一节。

## 2. 与 `DistanceTransform` 的关系：只是名字像

DT 滤波里的「距离」是**沿扫描线的一维积分**，逐通道、逐方向各算一次，不需要二维 EDT，也不需要
最近前景像素。本轮新增的 `DistanceTransformOps`（ANL-9）是精确二维平方欧氏距离场，两者没有共用代码，
也不互为前置条件。把 DT 滤波列进同一批，是因为名字容易被读成同一件事，这里明确切开。

## 3. 算术量与已有实测

一个通道、一次迭代、一个方向：1 次前缀积分 + 1 次信号递归 + 1 次归一化递归 = **3 个平面遍**；权重
`a_i` 只算一次，即每像素 1 次 `exp`。彩色 3 通道 × 2 方向 × 3 轮 = **54 个平面遍**、每像素 **18 次 `exp`**。
（下面统一用「平面遍」计数：一次箱均值处理一个通道平面算一遍。）

对照本库已实测的同类算子（4K Rgba8，同机）：

| 算子 | 4K 实测 | 平面遍 | 备注 |
|---|---|---|---|
| `GaussianBlur` σ=3 | **64 ms** | 2（可分离，向量化） | 不按通道拆 |
| `Bilateral` r=2 | **184 ms** | 25 tap 的邻域 | 行带并行 |
| `GuidedFilter` r=4（自导向） | **582 ms** | 12 遍箱均值（每通道 4 遍） | O(1)/px，与半径无关 |
| `GuidedFilter` r=4（cross guide） | **774 ms** | 18 遍箱均值（每通道 6 遍） | 本轮新增 |
| DT 滤波（估算，未实现） | **约 2.2 s** | 54 遍串行 | 每像素 18 次 `exp` |

估算方法：`GuidedFilter` 的 582 ms 对应 12 个平面遍 + 3 次平面构建，约 45 ms/遍；cross 的 774 ms 对应
18 遍，约 42 ms/遍，两个读数互相印证。DT 的 54 遍按 40 ms/遍算约 **2.2 s**，递归遍只多一次乘加，代价
主要来自 54 遍本身与每像素 18 次 `exp`。**未实现、未实测，故只作量级判断，不作承诺。**

## 4. 为什么这与本库的口径冲突

1. **横向遍不能向量化**：`y[i]` 依赖 `y[i−1]`，是行内串行前缀。`GuidedFilter` 的箱均值也有一层前缀和，
   但它只在 `prefix` 上串行、窗口相减可八像素并行；DT 的递归没有这个可并行的后半段。
2. **`exp` 是地板**：与 NLM 同一口径（`known-gaps.md` 记过「exp 是 SIMD 之后的地板」）。要么每像素
   18 次 `MathF.Exp`，要么把 `|Δct|` 量化查表 —— 后者把算子从 D1 降到 D2，且引入一张需要版本化的表。
3. **卖点已被覆盖**：论文相对 bilateral 的核心优势是「代价不随 σ 增长」。本库的 `GuidedFilter` 用箱均值
   已经做到 O(1)/px 且与半径无关，平面遍数只有其 1/4.5（12 对 54）。
4. **参数语义不映射**：`σs` / `σr` / 轮数三者耦合，论文的 NC/IC/NR/IR 是四种不同的细节层语义。我们要
   新增一个算子名，就得同时回答「它和 `GuidedFilter` 差在哪、什么时候该选它」，现在还答不上来。

## 5. 复评触发条件

只有下列任一条件成立时才值得重新打开：

- 出现「必须用一张引导图做**细节增强**（不是平滑）」的需求，且 `LocalLaplacian` 的观感不满足；
- 需要视频/逐帧处理，且实测表明 DT 的每帧代价低于现有三者的组合；
- 有独立的参考实现（论文伪代码或公开的 CC0 实现）可以逐像素对拍 —— 按仓库的 clean-room 规则，
  不能读 GPL 实现来「对齐」。

在此之前，`GuidedFilter`（含本轮新增的 cross guide）是保边平滑的正确答案：O(1)/px、可切带、D1、已有测试。
