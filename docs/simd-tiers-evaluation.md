# 第四档（AVX-512）：能评估什么，不能评估什么

**结论：本轮不出数。** 开发机 `avx512=False`（AMD Ryzen 7 7735H，AVX2 / V128 可用），四档矩阵只跑到三档；
"第四档已验证"这句话在没有硬件的机器上不成立，本文只写评估方法与预期收益，不写读数。

机器口径：本机（x64，AVX2，无 AVX-512），2026-11-14，`benchmarks/simd-tiers.sh` 与 `docs/known-gaps.md`。

## 1. 今天"第四档"实际会发生什么

`.NET` 的 `Vector256<T>` 在支持 AVX-512 的机器上仍然用 256 位子集执行，`Vector512<T>` 只有
`Vector512.IsHardwareAccelerated` 为 true 时才是 512 位指令。本库所有内核都写在 `Vector128/Vector256`
上并用 `IsHardwareAccelerated` 分派，因此：

- 在一台有 AVX-512 的机器上跑今天的代码，跑的是**同一套 AVX2 内核**，只是 CPU 更新、频率可能不同。
- 这**不构成**"第四档已验证"：没有任何一条指令是 512 位的，跨档逐字节一致也说明不了 512 位路径的正确性。
- `benchmarks/simd-tiers.sh` 因此只报三档；加一档需要先有 512 位内核，而不仅是把环境变量打开。

## 2. 哪些内核值得写 512 位，按预期收益排序

| 内核 | 现状 | 512 位能带来什么 | 风险 |
|---|---|---|---|
| `Median3x3`（16 lane 字节域） | 已向量化，1080p 575 → 0.8 ms | 32 lane，排序网络步数不变、吞吐翻倍 | 中位数网络的 shuffle 常量要按 512 位重排，容易写错且难以对拍 |
| `Convolve2D` / `BokehBlur`（移位行累加） | 已向量化，169/81 taps | 一次处理 16 个 float，tap 循环减半 | 需要 `Vector512<float>` 的 FMA，JIT 支持已就绪 |
| `NonLocalMeans` 的 SSD | AVX2 整数 abs-diff-sum | `VPDPBUSD`（VNNI）能把"乘加"合成一条指令，理论 2–4× | 距离项是 NLM 的地板；但整算子仍被 `exp` 主导（M11 实测），Amdahl 上限低 |
| ICC 的 3D CLUT | 标量（M13 实测否决向量化） | `VPMULLQ` 让 int64 累加可向量化，配合 `vpgatherdd` | 实测 CLUT 只占整条变换约 9%，即使 4× 也只省 2%；**不建议** |
| 字节域 LUT（点算子快路径） | 标量查表 | AVX-512 **VBMI 的 `vpermb`** 可做 64 字节表内 gather | 点算子当前不是瓶颈（M2 结论），收益待测 |

一句话：**先做 `Median3x3` 与 `Convolve2D`，NLM 次之，CLUT 不做**。排序依据是"该内核在整算子里的占比 ×
向量化倍数"，ICC 的 CLUT 两项都低。

## 3. 真要落地时必须先立的规矩

1. **`IlcInstructionSet=avx2` 不能动**（`AGENTS.md`）：AOT 基线是 AVX2，改成 `avx512` 会让 ILC 在无
   AVX-512 的部署机上生成非法指令。512 位内核只能走运行时分派。
2. **三档一致 → 四档一致**：新内核必须与现有标量孪生**逐字节**相同，`simd-tiers.sh` 的 body SHA 是判据，
   不是"看起来一样"。
3. **没有硬件就不合并**：本机无法执行 512 位路径，写出来的代码只能靠代码评审保证正确性——这正是本仓库
   拒绝的做法（"不宣称未验证的东西"）。可行的替代是借一台支持 AVX-512 的机器跑 `simd-tiers.sh`，
   在报告里写清机器型号与 `avx512=True`。
4. **评估要带消融**：新内核必须能在同一进程里 `ForceScalar` / 256 / 512 三路对拍 + 计时，否则无法把
   "指令更宽"与"频率下降"分开——AVX-512 在部分 CPU 上会降频，实测可能反而更慢。

## 4. 何时回来做

- 有一台 `avx512=True` 的机器（且能跑 `run.sh` 的 AOT 三路比对）。
- 或者 `Median3x3` / `Convolve2D` 在真实负载里的占比上升到值得优化（当前 1080p 上分别是 0.8 ms 与数十 ms）。

在此之前，第四档在 `docs/architecture.md` §11 与 `README.md` 里一律写"预留、未实现、未在硬件执行"。
