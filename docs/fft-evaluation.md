# FFT deconvolution: the evaluation, and why it is not in the library

**结论：不落地。** 直接卷积在当前参数范围内既更快也更好验证；FFT 要到 `σ ≈ 18 px` 以上才有算术优势，
而那个尺度上本库的 `MaxScratchBytes` 与 D1 纪律会先成为问题。本文把测得的数字和推导写清楚，供 M15 复评。

机器口径：本机（x64，AVX2，无 AVX-512），2026-11-14，`benchmarks/SimdImaging.Benchmarks`，1080p Rgba8，
`best of 1` 预热后单次读数。协议见 `benchmarks/README.md`。

## 1. 直接路径实测

| 场景 | 耗时 | 每次迭代 | 每像素每次迭代的乘加 |
|---|---|---|---|
| `rl 1080p sigma=1.5 it=10` | **254 ms** | 25.4 ms | 2 卷积 × 2 遍 × 11 tap ≈ 44 |
| `rl.motion 1080p len=15 it=10` | **347 ms** | 34.7 ms | 2 卷积 × 15 tap ≈ 30（稀疏 2D） |

高斯 PSF 半径 `ceil(3σ)`，σ=1.5 → 5；可分离两遍共 `2·(6σ+1) = 22` 个 tap。运动 PSF 走稀疏 tap 表，
长度 15 就是 15 个 tap —— 比同尺寸的稠密 `(2r+1)² = 225` 少一个数量级。

## 2. FFT 路径的算术量

设图像 `N×N`（1080p 补零到 2048²），一次复数 2D FFT 的浮点运算量按 `5·N²·log2 N` 估计：

```
N = 2048, log2 N = 22  →  5 × 4.19e6 × 22 ≈ 4.6e8 FLOP / 变换
```

每次 RL 迭代需要 4 次变换（估计的正变换 + 反变换、比值的正变换 + 反变换；PSF 频谱一次预计算后可复用）：

```
4 × 4.6e8 = 1.84e9 FLOP / 迭代
```

对照直接路径：`2.07e6 px × 44 = 9.1e7 FLOP / 迭代`。

**在 σ=1.5 上，FFT 的算术量是直接卷积的约 20 倍。** 交叉点由下式给出：

```
直接：每像素 2 卷积 × 2 遍 × (6σ+1) ≈ 4(6σ+1) FLOP
FFT ：每像素 4 × 5 × log2 N ≈ 440 FLOP
4(6σ+1) ≈ 440  →  σ ≈ 17.7
```

即 **σ ≳ 18 px** 时 FFT 才开始有算术优势；1080p 上这个 σ 意味着 PSF 直径 108 px，属于「严重失焦/长曝光」
而非本库默认的应用区间。运动 PSF 更不利：稀疏 15 tap 的直接卷积每像素约 30 FLOP，FFT 要赢需要
`log2 N` 小到不现实。

## 3. 为什么算术之外还有一层

即使某个参数组合上 FFT 更快，它也与本库的确定性契约冲突：

1. **累加顺序**：FFT 是 `log2 N` 级蝶形，不同档位（AVX2 / 无 AVX2 / 纯标量）与不同库实现会用不同的
   radix 分解与蝶形顺序；浮点加法不结合，结果必然在末位分叉。要做到 D1 只能冻结一份标量 FFT
   （禁止 `Vector.Sum`、禁止重结合），实测那比向量化版本慢 3–5×，正好抵消掉优势。
2. **旋转因子**：`Math.Cos/Sin` 与 `MathF` 版本在各架构上的位模式未在硬件上验证过（与 `Math.Exp`
   同一口径，见 `known-gaps.md` 的 M9/M12 行）。用查表替代会引入另一套需要版本化的常量。
3. **内存**：2048² 复数缓冲 = 32 MB（单精度），双精度 64 MB；再加 4 张 1080p 平面（RL 现在约 97 MB），
   峰值翻倍，而 `ProcessingPlan.EstimateWorkingBytes` 本来就看不到算子内部 scratch（`known-gaps.md` 已记）。

## 4. 复评触发条件

只有在下列任一条件成立时才值得重新评估：

- 出现「必须处理 σ ≥ 18 px 的失焦图」的需求，且 254 ms 的 1080p 直接路径不可接受；
- 需要在一个调用里对**同一张图**做多次不同 PSF 的反卷积（PSF 频谱可复用，直接路径不能）；
- D1 契约被明确放宽到 D2 并给出容差。

在此之前，直接卷积是正确答案：它每像素 44 次乘加、254 ms、D1、零新依赖、代码 260 行。
