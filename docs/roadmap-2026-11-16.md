上一版路线列了八项。其中两项的前提已被当天的实测推翻，一项已经做完。下面是逐项核对和修订后的清单。

## 二、关于 NLM：先消融，再决定算法

`6676 ms / 2.07 MPix = 3.2 µs/像素`。S=3、P=1 时每个像素要算 `(2·3+1)² = 49` 个偏移，每个偏移一次
`patch(3×3×4ch)` 的 SSD、一次 `sqrt`、一次 `expf`：

```
49 × (36 次乘加 + 1 sqrt + 1 expf) ≈ 1764 MAC + 49 sqrt + 49 expf
```

按 3.2 µs 反推，每 MAC 约 1.8 ns——**慢得不像纯算术问题**。`expf` 一个约 20–40 周期，49 个就是
1000–2000 周期/像素，很可能占大头。**滚动 SSD 只省「patch 求和」那一段，动不了 `expf`。**

上一版没做这一步就先选了算法——而当天 seam 的教训正是：**消融之前不要优化**（Energy 看着像大头，
实测只占 17%）。

所以第 2 项拆成两步：

1. **消融**（半天）：把 NLM 内层按 SSD / sqrt / exp / 访存分别计时，给出占比。
2. **按占比选**：
   - `expf` 主导 → **权重查表**（整数 SSD 索引 → 权重，Q15），外加**早退**（SSD 超过 3σ 截断直接跳过）；
   - SSD 主导 → **滚动 SSD**（整行/整列复用，patch 和增量更新）；
   - 访存主导 → **行带 + 缓存分块**，与融合执行器对接。

## 四、选 NLM 作为下一项的理由（同意上一版）

1. 它是**已存在的能力**变快，不是加算子凑数；
2. 差距是**数量级**的（0.3 MPix/s），不是几个百分点；
3. 有明确的对拍面：不改变语义，输出必须与现在逐字节一致，`known-gaps` 的纪律直接适用；
4. 不需要新硬件、不改公开 API。

唯一与上一版的分歧：**不要先写滚动 SSD**。当天 seam 的教训是消融先行，而 `expf` 很可能才是大头。
